### 问题 #1：商品信息混淆（并行任务串台）

- **发生版本**：v3
- **所在环节**：agent-flow Step 2~4
- **问题描述**：
  - 两个任务 (d1f1857e=ZARAH, 6938ec2a=AquaFlask) 并行执行
  - AquaFlask 的 Page 进入 Agent 模式后，`/chat` 路由显示 ZARAH 刚创建的活跃对话
  - AquaFlask 的图片和 prompt 被发送到 ZARAH 的 chat 会话中
- **根因**：
  - 同一 BrowserContext 下多 Page 共享 TikTok 账号会话
  - `/chat`（无 ID）路由默认展示最近活跃对话
- **修复**：
  - 在 `agent-flow.ts` 插入 Step 1.5：调用 `startNewChat(page)` 创建新会话
  - 通过 locator `text=/Start new chat/i` 点击按钮
  - 增加旧对话内容检测 fallback
- **验证**：v5 日志确认 startNewChat ✅ 成功，每个任务获得独立 chat ID

### 问题 #2：图片重复上传导致 DOM 失效

- **发生版本**：v2
- **所在环节**：shared-steps `uploadProductImages`
- **问题描述**：
  - 每张图片都重新点击"+"按钮、打开菜单、触发 fileChooser
  - 重复点击"+"导致下拉菜单 DOM 状态不一致 → "Element is not attached to DOM"
- **根因**：`for` 循环逐张上传，每次都重新走完整的点击流程
- **修复**：
  - 重构为 `fileChooser.setFiles(imagePaths)` 一次性上传所有图片
  - 只需点击一次"+" → "Upload images" → 一次传入所有路径

### 问题 #3：CONTENT_REJECTED 仍被重试

- **发生版本**：v5
- **所在环节**：agent-flow → index.ts executeTask
- **问题描述**：
  - Seedance 检测到人脸后抛出 `ContentRejectedError`
  - 但任务仍被 240s 后重新入队
  - `contentRejected` 字段从未被设置
- **根因**：
  - `executeAgentFlow` catch 块只允许 `NeedsManualError` 上抛
  - `ContentRejectedError` 被转为 `{ success: false }` 返回
  - `executeTask` 的 else 分支创建新 `Error('自动化流程返回 success=false')` 传给 `recordFailure`
  - `classifyError` 无法从通用 Error 中识别出 CONTENT_REJECTED → 走 UNKNOWN → 触发重试
- **修复**：
  - `agent-flow.ts` catch 块增加 CONTENT_REJECTED 上抛条件：
  ```typescript
  if (
    err instanceof NeedsManualError || (err as any)?.code === 'NEEDS_MANUAL' ||
    (err as any)?.code === 'CONTENT_REJECTED' || (err as any)?.name === 'ContentRejectedError'
  ) {
    throw err;
  }
  ```

### 问题 #4："Element is not attached to DOM" 大量失败

- **发生版本**：v5
- **所在环节**：shared-steps `inputPromptAndSend` 第 198 行
- **问题描述**：
  - 发送 prompt 后 URL 从 `/chat` 变为 `/chat/{chatId}`（消息已成功发送）
  - 验证逻辑检测输入框 textContent = "Describe any changes you want..."（新页面 placeholder）
  - 误判为"输入框未清空=消息未发送"
  - 兜底逻辑执行 `await inputEl.click({ force: true })` — inputEl 是旧 DOM 引用
  - 页面已导航重建 DOM → 抛 "Element is not attached to the DOM"
- **根因**：
  - 缺少 URL 变更检测（URL 含 chat ID = 发送成功）
  - 兜底时未重新获取 DOM 引用
- **修复**：
  ```typescript
  // 关键判断：URL含chat ID = 消息已发送成功
  const urlHasChatId = /\/chat\/\d+/.test(sendCheck.url);
  if (urlHasChatId) {
    return; // 提前返回
  }
  // 兜底时重新获取DOM引用
  const freshInput = await page.$('.tiptap.ProseMirror, ...');
  ```
