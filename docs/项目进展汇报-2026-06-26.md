### 1.2 新增功能

**1. AI 受众分析 Agent（图文双路融合）** — v0.6.0
文本路（Qwen）与图片路（Qwen-VL）并行分析，再由 LLM 融合输出最终受众画像，解决视频内容缺乏精准受众定位的问题。支持三种自适应路径：双路融合 / 纯视觉 / 纯文本兜底。

**2. 国家识别能力（零 LLM 调用，13 国覆盖）** — v0.7.0
基于 URL 域名自动识别目标国家，零 LLM 调用、毫秒级响应，覆盖 Lazada / Shopee / Amazon 等 13 个平台，自动映射 persona（人物形象）与 videoLanguage（输出语言）。

**3. Prompt 模板引擎（6 变量自动替换）** — v0.7.0
支持 `{productName}` / `{audience}` / `{sellingPoints}` / `{country}` / `{persona}` / `{videoLanguage}` 六个模板变量自动替换，消除手动拼接易出错的问题，实现 Prompt 标准化复用。

**4. 并发任务隔离（startNewChat）** — v0.8.0
每个 Agent 模式任务创建独立会话（startNewChat），防止并行任务商品信息串台，解决 06-16 批量执行中暴露的核心并发问题。

**5. CONTENT_REJECTED 不可重试错误体系** — v0.8.0
新增 CONTENT_REJECTED 错误码，标记为不可重试（直接标记 failed），避免人脸拒绝等内容审核问题浪费重试配额。

**6. 人脸检测与裁剪预处理** — v0.8.0
上传前通过 Qwen-VL 检测商品图是否含人脸，含人脸时使用 Sharp 自动裁剪/模糊处理，规避 Seedance 内容审核硬性拒绝。

**7. 全链路时间戳记录** — v0.8.0
新增 `TaskTimestamps` 类型，记录各阶段开始/结束时间，实现耗时可视化，便于性能分析和瓶颈定位。

**8. 生成完毕截图功能** — v0.8.0
视频生成完成后自动截图保存，提供可视化凭证，便于审核确认和问题排查。

**9. 截图监控集成** — v0.8.0
新增 `screenshot-monitor.ts`，在关键流程节点自动截图监控，流程异常时快速定位问题发生位置。

**10. Agent 入口三阶策略** — v0.8.0
Agent Tab 优先 → DOM 文本搜索（位置过滤排除全局工具栏误匹配）→ 侧边栏兜底，三阶递进确保平台改版后入口仍可定位。

**11. 图片批量上传重构** — v0.8.0
重构为 `fileChooser.setFiles` 一次性上传多张图片，避免重复触发 + 按钮导致 DOM 失效，解决 06-16 批量执行的核心阻塞问题。

### 1.3 优化增强

**1. 选择器全面适配新版 UI** — v0.8.0
新版建议按钮、Looks good 按钮等非标准 button 元素全面适配，解决 TikTok UI 改版后选择器失效导致流程中断的问题。

**2. inputPromptAndSend DOM 防脱落** — v0.8.0
增加 URL chatId 检测 + DOM 引用刷新机制，解决 "Element is not attached to DOM" 大量失败的问题。

**3. 视频生成检测修正（精确匹配进度元素）** — v0.8.0
精确匹配进度元素而非模糊匹配，避免误判导致视频生成 20 分钟硬超时。

**4. 每日复盘机制增强** — v0.8.0
复盘文档结构优化，增加 AI 候选问题清单、近 7 天任务趋势等自动汇总区块，提升复盘信息丰富度。

**5. 审核面板新增受众分析按钮** — v0.6.0
新建任务表单增加「🎯 AI 受众分析」按钮 + audience 输入框，方便用户在创建任务时一键获取受众分析结果。

## 二、项目概述

### 2.1 项目定位

TikTok Symphony RPA 是一套面向 **TikTok 视频批量生成** 的自动化系统，基于 Playwright 浏览器自动化技术，实现从商品信息导入到视频生成、审核、下载的全链路自动化，目标是大幅降低视频制作人力成本，支撑大规模（≥10 条/批）视频批量生产。

**核心目标**：

- **全链路自动化闭环**：商品数据录入 → AI 前置分析（卖点/商品图/受众/国家）→ 视频生成（模板/Agent 双模式）→ 人工审核 → 自动下载
- **智能化前置分析**：通过 AI（Qwen LLM + Qwen-VL 视觉模型）自动提炼卖点、评分商品图、识别受众画像、识别目标国家
- **批量生产能力**：支持 JSON/Excel 批量导入，AI 自动补全缺失字段
- **稳定性与自愈**：选择器热更新、失败现场快照、错误分类与退避重试、登录态续期

### 2.2 技术选型

| 类别 | 技术方案 | 版本 |
|------|---------|------|
| 运行时 | Node.js 22（nvm 管理） + TypeScript | TS 5.7 |

| Web 服务 | Express | 4.21 |

| 数据处理 | xlsx | 0.18.5 |
| 前端面板 | 原生 HTML/CSS/JS（Express 托管） | — |
| 任务 ID | uuid | 11.1.0 |
| 开发工具 | ts-node 10.9 + nodemon 3.1 | — |

### 2.3 核心架构

```
商品数据录入 → AI前置分析(卖点/商品图/受众/国家) → 视频生成(模板/Agent双模式) → 人工审核 → 自动下载
```

**关键架构设计**：

- **双模式生成**：模板模式（复用 Symphony 模板库）与 Agent 模式（AI 对话驱动）
- **任务状态机**：`pending → running → waiting-generation → review → approved → downloading → completed`（含 `rejected`/`failed` 分支）
- **并发处理**：Page 池管理（当前配置 `maxPages=2`，降低并发避免 TikTok 限流），视频等待期释放 Page
- **人工审核闭环**：Web 审核面板支持一键通过/拒绝/重试
- **WebSocket 实时推送**：任务状态变更实时通知前端

### 5.2 v0.6.0：AI 受众分析 Agent

```
商品链接
  ├─ scrapeProductPage ──→ 页面文本 ──→ Qwen(文本模型) ──→ 文本路受众
  │                                                           │
  ├─ scrapeProductImages ──→ 图片URL ──→ Qwen-VL(视觉模型) ──→ 图片路受众
  │                                                           │
  └─────────────────── Qwen(融合) ◄──── 合并两路结果 ◄────────┘
                            │
                       最终受众描述 → 融入 Prompt 的 Target Audience 段
```

**三种自适应路径**：

| 路径 | 条件 | 效果 |
|------|------|------|
| 双路并行 + LLM 融合 | 文本 + 图片都有 | 最佳效果 |
| 纯视觉模型分析 | 仅图片（本地商家文字少） | 适合图片为主场景 |
| 纯文本模型分析 | 仅文本 | 兜底 |

**图片路 Qwen-VL 判断维度**：产品品类识别、目标人群推断（年龄/性别/生活方式）、使用场景、定位档次（包装设计暗示）、视频调性建议

### 5.3 v0.7.0：国家识别 + Prompt 模板引擎

**国家识别能力**：

- 基于 URL 域名自动识别，**零 LLM 调用、毫秒级响应**
- 覆盖 **13 个国家/地区**（Lazada / Shopee / Amazon / Tokopedia / Tiki / Coupang 等）
- 自动映射 `country → persona`（人物形象）+ `videoLanguage`（输出语言）

**Prompt 模板引擎** — 支持 6 个模板变量，自动替换为实际值：

| 变量 | 含义 | 来源 |
|------|------|------|
| `{productName}` | 商品名称 | 用户输入 / 抓取 |
| `{audience}` | 目标受众 | AI 受众分析 Agent |
| `{sellingPoints}` | 卖点 | AI 卖点分析 Agent |
| `{country}` | 目标国家 | URL 自动识别 |
| `{persona}` | 视频人物形象 | country 映射 |
| `{videoLanguage}` | 视频输出语言 | country 映射 |

**最终 Prompt 提交结构**：
```
{用户的prompt}
Product: {商品名}
Target Audience: {AI生成的受众描述}
Key Selling Points: {卖点}
```

### 5.4 v0.8.0：批量执行稳定性全面加固

本次为 v0.6.0 以来最重要的稳定性迭代，针对 06-16 批量执行暴露的 5 类核心问题逐一修复：

| 问题 | 修复方案 | 涉及文件 |
|------|---------|---------|
| 并发任务串台（商品信息混淆） | 新增 `startNewChat` 创建独立会话 | agent-flow.ts, shared-steps.ts |
| 图片重复上传导致 DOM 失效 | 重构为 `fileChooser.setFiles` 一次性上传 | shared-steps.ts |
| CONTENT_REJECTED 人脸拒绝仍被重试 | catch 块增加 CONTENT_REJECTED 上抛条件 | errors.ts, manager.ts |
| "Element is not attached to DOM" | URL 含 chatId 检测 + 重新获取 DOM 引用 | shared-steps.ts |
| Agent 入口页面结构变更 | 三阶策略：Agent Tab 优先 → DOM 文本搜索 → 侧边栏兜底 | agent-flow.ts |

**Agent 入口三阶策略**：

```
策略1：Agent Tab 优先
  └─ 定位 [data-e2e="agent-tab"] 或文本含 "Agent" 的 Tab
      └─ 成功 → 进入 Agent 模式
      └─ 失败 ↓

策略2：DOM 文本搜索
  └─ 全页搜索含 "Agent" / "Symphony Agent" 文本的元素
  └─ 位置过滤：boundingBox().y > 100（排除全局工具栏误匹配）
      └─ 成功 → 点击进入
      └─ 失败 ↓

策略3：侧边栏兜底
  └─ 展开侧边栏 → 查找 Agent 入口
      └─ 成功 → 进入 Agent 模式
      └─ 失败 → 抛出错误 + 失败快照
```

**人脸检测与裁剪预处理流程**：

```
商品图上传前
  ├─ face-detect-agent.ts ──→ Qwen-VL 检测是否含人脸
  │     ├─ 无人脸 → 直接上传
  │     └─ 有人脸 ↓
  └─ face-crop.ts ──→ Sharp 裁剪/模糊人脸区域
        └─ 处理后图片 → 上传
```

**CONTENT_REJECTED 错误体系**：

| 错误码 | 含义 | 可重试 | 处理策略 |
|--------|------|--------|---------|
| SELECTOR_TIMEOUT | 选择器超时 | ✓ | 指数退避重试 |
| NAVIGATION_FAILED | 导航失败 | ✓ | 重试 + 选择器热更新 |
| LOGIN_REQUIRED | 登录失效 | ✓ | 挂起等待重新登录 |
| GENERATION_TIMEOUT | 生成超时 | ✓ | 退避重试 |
| ELEMENT_DETACHED | DOM 脱落 | ✓ | DOM 引用刷新重试 |
| **CONTENT_REJECTED** | **内容被拒绝（人脸等）** | **✗** | **直接标记 failed，不重试** |
| UNKNOWN | 未知错误 | ✓ | 退避重试 |
